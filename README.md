# Leadwise

Lead management CRM for a small real estate sales team. Leads come in from Meta lead ads (Facebook and Instagram) and Excel uploads, the owner shares them out, and each person works their own leads and follow ups. The backend is Express and Supabase.

> **Portfolio demo.** Leadwise is a demo version of a custom internal CRM I built for a real company. It is published only for portfolio purposes and runs on seed data only: every person, phone number, project, campaign, call and figure is synthetic and comes from the seed script. No company data is included. The Meta lead sync is built in but is not connected in the demo; the campaign leads you see were generated by the seed.

## What it does

* **Roles.** The owner sees every lead, projects, campaigns and users. An employee sees their own leads and the unassigned leads in their projects, and can only change leads assigned to them.
* **Leads.** Mine, Unassigned and All views with filters (project, priority, repeat enquiries, month or date range), edit, assign, reassign and bulk assign. Every change is logged with who, when, the old and new value and the reason.
* **Statuses.** New, Not Answered, Not Reachable, Switched Off, Call back later, Call after some time, Interested, Sent Details, Reg Done, Closed, Not Interested, Invalid Number and Lost. A lost lead needs a reason; a closed lead needs the deal amount. Closed and lost leads are locked.
* **Today's leads.** The owner shares today's unassigned leads equally across selected people.
* **Follow ups.** Overdue, today and upcoming call backs.
* **Booked.** Closed deals with their amount, who closed them and when.
* **Calls.** Calling a lead logs the call. Employees see their own calls; the owner also sees team calls.
* **Performance.** Closed deal value per person, split between everyone on the lead, with a leaderboard.
* **Projects (owner).** Add, rename, pause or delete a project and pick who works on it.
* **Campaigns (owner).** Meta connection status, campaigns with their lead counts, lead quality and lead sources.
* **Users (owner).** Invite, edit, deactivate or delete people, and hand their leads to someone else.
* **Excel upload.** Finds the name and phone columns, skips numbers already in the CRM (logged as a repeat enquiry) and rejects rows without a valid 10 digit number.
* **Sign in** with email and password, Google, or the demo accounts. Only addresses on the Users page get in.

## How it fits together

The React app signs in with Supabase Auth. Every read and write goes to one endpoint, `POST /api/rpc`, as `{ action, args, token }`. The API checks the token, loads the `users` row, applies the visibility rules and talks to Postgres with the service role key. It answers `{ ok: true, data }` or `{ ok: false, error }`.

The browser never writes to Postgres directly. The publishable key is used only for sign in.

The API runs TypeScript directly on Node 22.18 or newer, so it has no build step.

**Stack:** React 19, React Router 7, TanStack Query 5, Tailwind CSS 4, Vite 8, TypeScript 6, Express 5, Supabase (Postgres, Auth).

## Running it locally

You need Node 22.18 or newer and a Supabase project.

**1. Database.** In the Supabase SQL editor run `backend/supabase/schema.sql`, then `backend/supabase/crm_schema.sql`. Then in the Supabase dashboard:

* Authentication > Users: add the owner and employee yourself (tick Auto Confirm User) with one shared password. Put their emails in `DEMO_OWNER_EMAIL` and `DEMO_EMPLOYEE_EMAIL`.
* Authentication > Hooks: set Before User Created to `public.gate_signups`.
* Authentication > Providers: turn on Google if you want it.

**2. Environment.** Create `backend/.env` with the variables below. It is the only env file: the frontend reads it too, and only the values it maps reach the browser.

**3. Install, seed and start.**

```bash
cd backend
npm install
npm run seed
npm run dev
```

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173.

The seed clears the CRM tables and generates about six months of data: projects, Meta campaigns, leads from Meta and Excel uploads with their full history (assignments, calls, status changes, repeat enquiries, deal amounts), and a handful of fresh unassigned leads for today. It is deterministic, so every run gives the same data relative to today.

## Environment variables

One file, `backend/.env`, serves both apps.

* `SUPABASE_URL` (required): project URL.
* `SUPABASE_SECRET_KEY` (required): service role key. Never reaches the browser.
* `SUPABASE_PUBLISHABLE_KEY` (required): publishable key, used by the browser for sign in.
* `ALLOWED_ORIGINS` (required): comma separated web origins allowed to call the API. The first one is also where invite emails send people to set a password.
* `APP_NAME` (required): product name.
* `APP_TIME_ZONE` (required): IANA zone for business days, for example `Asia/Kolkata`.
* `PORT`: API port, 4000 when not set. In development the web app forwards `/api` to it.
* `DEMO_OWNER_EMAIL`, `DEMO_EMPLOYEE_EMAIL`: the seed uses them to find the owner and employee. With `DEMO_PASSWORD` set, the login page also shows one click demo sign in. Write a `$` in the password as `\$`. Leave `DEMO_PASSWORD` unset in production.
* `META_PAGE_TOKEN`: Meta page access token. Leave it unset for the demo.
* `META_FORM_IDS`, `META_AD_ACCOUNT`, `META_ADS_TOKEN`: optional. Limit the sync to these lead forms, and skip leads from campaigns that are no longer running.
* `VITE_API_URL`: full URL of the RPC endpoint when the web app is hosted apart from the API, for example `https://api.example.com/api/rpc`. Defaults to `/api/rpc`.

A host that builds the web app on its own can set `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_APP_NAME` and `VITE_APP_TIME_ZONE` directly instead.

## Scripts

**backend:** `npm run dev` (API with reload on save), `npm start`, `npm run seed` (reset and generate demo data), `npm run typecheck`.

**frontend:** `npm run dev`, `npm run build`, `npm run preview`, `npm run lint`, `npm run typecheck`.

## API

* `GET /api/health`: database check and latency. Public.
* `POST /api/rpc`: `{ action, args, token }`. Reads: `currentSession`, `listLeads`, `performance`, `callStats`, `listProjects`, `listUsers`, `listCampaigns`, `listSources`. Writes: `writeLead` (`update` or `assign`), `logCall`, `importLeads`, `writeProject`, `createUser`, `updateUser`, `deleteUser`, `setMetaConnected`. Owner only actions say so in the error.

## Deploying

**Database.** Run both SQL files on the production Supabase project, set the Before User Created hook, and add the production web address and its `/set-password` and `/login` paths to the Auth redirect URLs.

**API.** Any Node host (Render, Railway, Fly.io, a container). Install with `npm install`, start with `npm start`, and set the variables. `ALLOWED_ORIGINS` must include the production web origin. `GET /api/health` works as a health check.

**Web app.** Any static host. Run `npm run build` and publish `dist`. Route every path that is not a file to `index.html`. Either forward `/api` to the API on the same domain, or set `VITE_API_URL` before building.
